Marker and popup behavior in this project

Goal: make you confident changing marker visuals, popup placement, and popup open or close rules in the existing Parkrun map. This lesson stays inside the live implementation in app/locations/locations-map.tsx.

Mission link

Your mission is not “learn Mapbox in general.” It is narrower and more useful: confidently edit the marker and popup behavior already shipping in this app. That means the first seam to understand is the current React state flow, not the full Mapbox API.

Mental model

The popup is not inside the marker behavior-wise

In this repo, markers and popups are rendered near each other in JSX, but their behavior is split across two decisions:

Step 1
Marker renders

The marker gets a coordinate and custom SVG or div content through <Marker>.

Step 2
React state changes

Hover updates hoveredMarker. Click sends the selected Parkrun upward through onParkrunSelect.

Step 3
Popup appears

A conditional decides whether <Popup> exists for that marker.

If you remember only one thing from this lesson, remember this: marker styling lives in marker DOM, but popup visibility lives in React state plus a conditional render.
Current behavior
Parkrun markers

Custom SVG pin. Scale increases on hover or selection. Click selects the Parkrun and recenters the map via parent state.

Parkrun popups

Shown when a marker is hovered or selected. Current props include anchor="bottom" and closeButton={false}.

Home markers

Separate marker branch with its own hover state. Popup shows only on hover for home points.

Mapbox wrapper

This app uses react-map-gl/mapbox, so the relevant docs are the vis.gl Marker and Popup references first, then native Mapbox examples for intuition.

Change map

When you want to change behavior, start with this table

I want to change… First place to edit Likely change
Pin color, ring, scale, icon Marker child JSX SVG classes, wrapping div, conditional class logic
Popup position relative to the pin Popup props anchor and offset
Popup width or shell styling Popup props and inner popup markup maxWidth, className, body layout
Open on click, not hover State and event handlers Stop setting hover state as the open signal; rely on selection state instead
Close on background click or map movement Popup options closeOnClick, closeOnMove, onClose

Practice

Three quick retrieval checks

1. If the popup should sit 12px above the pin, what do you change first?

Change the popup props: keep the same coordinates, then add or adjust offset. This is a positioning concern, not a state concern. See the react-map-gl Popup API.

2. If the marker should turn green when selected, what do you change first?

Change the marker child JSX and its conditional classes. The selected state already exists; the visual expression of that state lives inside the marker DOM.

3. If hover should no longer open the popup, what do you change first?

Change the open condition and the hover handlers. Right now hover feeds hoveredMarker, and the popup renders when hover or selection is true. Remove hover from the decision, then check whether any hover-only styling should remain.

Tiny exercise

Do one safe change

Try this edit the next time you want hands-on practice:

  1. Add a small popup offset so the Parkrun popup sits a little above the pin.
  2. Set a popup max width so longer location labels feel deliberate.
  3. Reload the page and verify that hover, click, and close behavior still work.
Success condition: you can say why this was a Popup change and not a Marker or state change.
